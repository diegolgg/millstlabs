# Evaluation suites and metrics for game-playing LLM agents and multi-agent populations (as of Oct 2026)

Scope: (1) multi-game LLM-agent benchmarks/arenas, (2) rating + population-evaluation methodology, (3) population-level metrics, (4) statistical practice, (5) games shared across suites with fast simulators. Everything below is sourced inline; items I could not verify are flagged in "Gaps".

## KQ1. Multi-game LLM-agent benchmarks and arenas (games, metric, harness, overlap)

### Takeaway
There are now ~15 multi-game LLM suites; the three that matter most for a startup wanting a reusable API + comparability are **TextArena** (largest game set, Gym-style string API, TrueSkill leaderboard with humans), **Kaggle Game Arena** (DeepMind-backed, most rigorous rating methodology: Bradley-Terry Elo for chess, BB/100 with block bootstrap for poker, equilibrium "GTE" ratings for Werewolf, 40 games/pair and 20k hands/pair), and **OpenSpiel-based suites** (GTBench, Board Game Arena) whose 10 classical games are *all* also in TextArena. Every suite that reports multiple games finds that rankings are **not consistent across games** (Kaggle, lmgame-Bench, GTBench), which is itself the strongest argument for running your population on 2-3 games rather than one.

### Cited Findings

**Competitive / multi-player text-game arenas**

- **TextArena** (Guertler et al., arXiv 2504.11442, Apr-May 2025): "open-source collection of competitive text-based games"; abstract says "57+ unique environments (including single-player, two-player, and multi-player setups)"; "online-play system (against humans and other submitted models)"; "real-time TrueSkill scores"; licensed CC BY 4.0; "Work in progress" 5-page paper — [arXiv abs](https://arxiv.org/abs/2504.11442). The GitHub README now claims "100+ single-, two-, and multi-player text-based games", an "interface styled after OpenAI Gym", MIT license, and agents "only need to implement a `__call__` function that accepts a string observation and returns a string action" — [GitHub README](https://github.com/LeonGuertler/TextArena). The environment catalogue lists 28 single-player (incl. 2048, Sokoban, Wordle, TowerOfHanoi, Bandit, Mastermind, TwentyQuestions), 45 two-player (incl. Chess, ConnectFour, TicTacToe, KuhnPoker, LeducHoldem, Breakthrough, Nim, PigDice, IteratedPrisonersDilemma, IteratedMatchingPennies, IteratedRockPaperScissors, ColonelBlotto, SimpleBlindAuction, SimpleNegotiation, Battleship, Stratego, Othello, Checkers, Debate, TruthAndDeception) and 19 multi-player (incl. Poker 2-15, LiarsDice 2-15, Negotiation 2-15, BlindAuction 3-15, Codenames 4, Diplomacy 3-7, SecretMafia 6-15, Coup 2-6, Taboo 4-8, TwoRoomsAndABoom 6-20, Santorini 2-3, Snake 2-15) — [envs README](https://github.com/LeonGuertler/TextArena/blob/main/textarena/envs/README.md). The live leaderboard shows TrueSkill, games played, win rate, W/D/L and a "Human" column — [textarena.ai/leaderboard](https://www.textarena.ai/leaderboard).
- **SPIRAL** (Liu et al., arXiv 2506.24119, ICLR 2026) trains via self-play on three TextArena games (TicTacToe, Kuhn Poker, Simple Negotiation) "against continuously improving versions of themselves" and reports transfer "by up to 10% across a suite of 8 reasoning benchmarks on 4 different models", evaluated also on "seven out-of-distribution games" — [arXiv](https://arxiv.org/abs/2506.24119); [ICLR 2026 proceedings](https://proceedings.iclr.cc/paper_files/paper/2026/file/3ba7c8c36b71b2fc31fae3361aefefbf-Paper-Conference.pdf). (Relevant: shows TextArena is usable as a *training* substrate, not just an eval.)
- **Kaggle Game Arena** (Google DeepMind + Kaggle): launched with chess Aug 2025 ("hundreds of 'behind the scenes' games" for the leaderboard) — [Google blog, Aug 2025](https://blog.google/innovation-and-ai/products/kaggle-game-arena/); [SiliconANGLE](https://siliconangle.com/2025/08/04/google-deepmind-host-ai-chess-tournament-evaluate-leading-ai-models-reasoning-skills/). Expanded Feb 2, 2026 to poker and Werewolf; chess uses "Elo ratings", the Werewolf leaderboard uses an "Equilibrium Rating"; Gemini 3 Pro/Flash top both — [Google blog, Feb 2026](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/kaggle-game-arena-updates/). Technical report "Game Arena: Strategic LLM Evaluation in Competitive Environments" (arXiv 2609.31473, Sep 2026): three pilot environments Chess, Poker, Werewolf; "model strength is sharply stratified within each game environment, but not consistent across games"; Gemini 3 Pro "leads the Chess ranking, yet has negative returns in Poker" — [arXiv abs](https://arxiv.org/abs/2609.31473v1). Methodology from the HTML: chess = "Elo-style ratings derived from the Bradley-Terry model" with "the lowest-rated model [set] to 0", "40 games/pair" colour-balanced; poker = BB/100 with "block bootstrap over episodes", "20,000 hands/pair" over a 10-model round robin = "900,000 hands in total"; Werewolf = game-theoretic evaluation (GTE) that "decomposes each model's overall skill into role-specific contributions" over "~31,500 total games"; illegal moves: chess "If a model fails after four attempts, the game ends with a loss"; poker "a second consecutive illegal action defaults to the most conservative action"; "uniform, text-based harness"; 10 models from OpenAI, Anthropic, Google, xAI, DeepSeek; "competitive games probe distinct dimensions of strategic competence" — [arXiv HTML](https://arxiv.org/html/2609.31473v1). The Werewolf rating "reframes the full game as a simplified three-player meta-game: one player selects a role, and two competing managers choose models for that role", solved with the "polarix library", "allows for non-transitive performance cycles"; Elo/TrueSkill "assume transitive skill and do not model role-specific contributions" — [Kaggle Werewolf leaderboard (via search summary)](https://www.kaggle.com/benchmarks/kaggle/werewolf). A Feb 2026 press report also lists "Four in a Row" as a Game Arena game — [GIGAZINE](https://gigazine.net/gsc_news/en/20260203-google-kaggle-game-arena-poker-and-werewolf/) (not confirmed by Google's own post; see Gaps).
- **Werewolf Arena** (Google, arXiv 2407.13943, Jul 2024): bidding-based turn-taking ("agents bid on urgency levels (0-4) to speak"); each matchup "10 games with models alternating between werewolf and villager roles (5 games each)"; Gemini 1.5 Pro vs GPT-4 etc.; code at github.com/google/werewolf_arena — [arXiv HTML](https://arxiv.org/html/2407.13943v1); [GitHub](https://github.com/google/werewolf_arena).
- **GTBench** (Duan et al., NeurIPS 2024, arXiv 2402.12348): 10 games — Tic-Tac-Toe, Connect-4, Kuhn Poker, Breakthrough, Liar's Dice, Blind Auction, Negotiation, Nim, Pig, Iterated Prisoner's Dilemma; metric = Normalized Relative Advantage (NRA) in [-1, 1]; "50 valid matches" per competition with first-player alternation (25/25); opponents = MCTS with 1000 simulations (Tit-for-Tat for IPD), random baselines; "all of the gaming environments are built on top of OpenSpiel"; code github.com/jinhaoduan/GTBench — [arXiv HTML](https://arxiv.org/html/2402.12348). Headline: "LLMs fail in complete and deterministic games yet they are competitive in probabilistic gaming scenarios" — [arXiv abs](https://arxiv.org/abs/2402.12348).
- **Board Game Arena / Game Reasoning Arena** (arXiv 2508.03368, Aug 2025): "uses Google-DeepMind's OpenSpiel library as the underlying game engine"; games incl. Tic-Tac-Toe, Connect Four, Kuhn Poker, Prisoner's Dilemma, Matching Pennies; metrics = average/max cumulative reward, "decision optimality (proportion of moves matching equilibrium policy)", error rates, reasoning categorisation; Ray-parallel, LiteLLM/vLLM backends; docs at board-game-arena.readthedocs.io — [arXiv HTML v1](https://arxiv.org/html/2508.03368v1). (Note: the PDF title is "Game Reasoning Arena" — [PDF](https://arxiv.org/pdf/2508.03368) — same paper, renamed.)
- **SPIN-Bench** (Yao et al., arXiv 2503.12349, Mar 2025): PDDL (21 domains, 1,280 tasks) + Tic-tac-toe, Connect Four, Chess (vs minimax / dedicated solver / Stockfish levels 0-20) + Hanabi (2-5 players, score out of 25) + Diplomacy (supply centres, order success, negotiation alignment); "10 repetitive games" for simple games and "4 repetitive games" for chess; o1: 58.59% planning accuracy, Hanabi 2-player 16.4, Diplomacy move-success 0.70; human Hanabi reference from "54,977 historical games" — [arXiv HTML v1](https://arxiv.org/html/2503.12349v1); [GitHub](https://github.com/spinbench/spinbench).
- **GameBench** (Costarelli et al., arXiv 2406.06613, Jun 2024): 9 games — Air, Land, Sea; Arctic Scavengers; Are You the Traitor?; Codenames; Hive; Pit; Santorini; Two Rooms and a Boom; Sea Battle. Aggregation = "exponential Bradley-Terry model"; "bootstrapping on the sample S for B=10,000 times" for CIs; "random baseline and faster games were oversampled due to their low cost"; single human baseline outperformed all LLMs; code github.com/Joshuaclymer/GameBench (CC-BY 4.0) — [arXiv HTML](https://arxiv.org/html/2406.06613v1).
- **GAMA-Bench** (Huang et al., arXiv 2403.11807, 2024): 8 classic multi-agent economics games (Guess 2/3 of the Average, El Farol Bar, Divide the Dollar, Public Goods, Diner's Dilemma, Sealed-Bid Auction, Battle Royale, Pirate Game); each game 0-100, overall = mean; 10 agents per model, T=1.0, 20 rounds, "each game was executed five times"; variance across temperature 3.4 but prompt-rephrasing variance up to 23.7 (Diner's Dilemma) — [arXiv HTML](https://arxiv.org/html/2403.11807).
- **clembench** (Chalamalasetti et al., EMNLP 2023; arXiv 2305.13455): v1.0 games taboo, wordle (x3 variants), drawing, reference, private/shared; 250 instances total; "Clemscore is the macro-average quality score multiplied by the macro-average proportion of played games"; framework clemgame — [ar5iv](https://ar5iv.labs.arxiv.org/html/2305.13455); [ACL Anthology](https://aclanthology.org/2023.emnlp-main.689/). Current: clembench v3.0 (Apr 15, 2026) and clemcore 3.4.2 (Jan 28, 2026); live leaderboard tracks clemscore, % played, quality — [clp-research/clembench](https://github.com/clp-research/clembench); [clemcore](https://github.com/clp-research/clemcore); [leaderboard](https://clembench.github.io/leaderboard.html); [“Third Paradigm” paper 2507.08491](https://arxiv.org/html/2507.08491v1).
- **GameArena (live computer games, UCSD)** (Hu et al., arXiv 2412.06394, Dec 2024): three games with humans in the loop, "over 2,000 game sessions", five LLMs — [arXiv abs](https://arxiv.org/abs/2412.06394). Distinct from Kaggle Game Arena despite the name.

- **lmgame-Bench** (Hu et al., ICLR 2026, arXiv 2505.15146): Sokoban, Super Mario Bros, Tetris, 2048, Candy Crush, Ace Attorney; progression vs long-horizon rewards; "over three runs" (some single-run); "Sokoban shows strong correlations with math and coding benchmarks"; RL on Sokoban "boosting Blocksworld 1D/2D by at least 10%, and ... up to 8% zero-shot improvement on Tetris"; harness github.com/lmgame-org/GamingAgent — [arXiv HTML](https://arxiv.org/html/2505.15146); [GitHub](https://github.com/lmgame-org/GamingAgent).

### Inferences
- For "several games behind one API", TextArena is the only LLM-native suite where a single string-in/string-out agent interface covers chess, poker variants, negotiation, social deduction and puzzles; GTBench/Board Game Arena give the same classical games with an equilibrium-policy reference (via OpenSpiel solvers) which TextArena lacks.
- Kaggle Game Arena is the de-facto external yardstick: if your population's chess/poker/Werewolf play can be exported to its harness format you get direct comparability with frontier-model ratings; its per-game rating choices (BT-Elo, BB/100, GTE) are a ready-made template.
- Rankings disagree across games in every multi-game study found (Kaggle, lmgame-Bench correlation analysis, GTBench deterministic-vs-probabilistic split); a single-game metric will overfit to that game.

### Gaps
- TextArena's TrueSkill parameters (initial mu/sigma, beta, draw handling) and the exact game count are not documented in the paper (57+) and differ from the README (100+) and catalogue (92 listed + others); treat counts as approximate.
- "Four in a Row" on Kaggle Game Arena is reported only by GIGAZINE; Google's Feb 2026 post names chess, poker, Werewolf only.
- Kaggle leaderboard pages did not render (JS); GTE/"Equilibrium Rating" details came from the arXiv report and a search summary of the leaderboard page.
- DSGBench, GVGAI-LLM, ChessArena, TTT-Bench, WGSR-Bench, CHBench not fetched; names/IDs only.

## KQ2. Methodology for evaluating populations (ratings, Nash-based, league/frozen ladders, intransitivity, exploitability, cross-play, ad-hoc teamplay, Melting Pot)

### Takeaway
The field's consensus: Elo is unreliable for LLM head-to-head data (order- and K-sensitive, assumes transitivity); use **Bradley-Terry with bootstrap CIs** for pairwise games, **TrueSkill** only when you need online multi-player updates (needs roughly 3-12 games/player for FFA, more with teams), and **Nash-based ratings** (Nash averaging, alpha-rank, Deviation Ratings, VasE maximal lotteries, Kaggle's GTE) when cycles matter. For *populations*, the DeepMind lineage (AlphaStar league, Balduzzi 2019, Czarnecki 2020) gives the standard: freeze past generations, compute a cross-play payoff matrix, and report **relative population performance** at Nash plus **Nash clustering** to measure intransitivity; the minimum useful population size is the width of the widest non-transitive layer.

### Cited Findings

**Elo / Bradley-Terry / Glicko / TrueSkill and games-per-rating**

- TrueSkill (Microsoft Research) convergence table, minimum games per player: 16-player FFA 3; 8-player FFA 3; 4-player FFA 5; 2-player 12; 4 teams x 2 = 10; 4 teams x 4 = 20; 2 teams x 4 = 46; 2 teams x 8 = 91; "the actual number of games needed per gamer can be up to three times higher" — [Microsoft Research TrueSkill page](https://www.microsoft.com/en-us/research/project/trueskill-ranking-system/). Defaults mu0=25, sigma0=25/3, beta=25/6, tau=sigma0/100; leaderboards display the conservative "mu - 3 sigma" — [Wikipedia TrueSkill](https://en.wikipedia.org/wiki/TrueSkill).
- Glicko: Glickman recommends rating periods averaging "5 to 10 games" per player; RD is the uncertainty, 95% interval = rating +/- 2 RD — [Glicko paper](https://www.glicko.net/glicko/glicko.pdf); [Glicko for beginners](https://www.englishchess.org.uk/wp-content/uploads/2012/04/The_Glicko_system_for_beginners1.pdf).
- Chatbot Arena (LMSYS, arXiv 2403.04132): moved to Bradley-Terry MLE with bootstrap / sandwich-robust CIs; ~240,000 votes, >50 models (Jan 2024); to estimate the win matrix to precision 0.2, random sampling needed 6,800 samples vs 4,400 with active sampling (35% saving); for score precision 0.3, 17,200 vs 16,400 — [arXiv HTML](https://arxiv.org/html/2403.04132). Blog: BT "treats model performance as fixed", multinomial bootstrap with 1000 resamples, 2.5/97.5 percentiles — [LMSYS blog Dec 2023](https://www.lmsys.org/blog/2023-12-07-leaderboard/).
- "Ranking Unraveled" (arXiv 2411.14483): compares Elo, Bradley-Terry, Glicko, Markov chain on LLM head-to-head data; Elo "even with >> 1,000 permutations, struggles to achieve stable rankings"; BT best transitivity preservation (77.29% Arena vs Elo 68.24%); recommends "Avoid Elo", BT for controlled datasets, Glicko for large uneven datasets; ideal K "less than the standard 32" — [arXiv HTML](https://arxiv.org/html/2411.14483).
- "Elo Uncovered" (Boubdir et al., GEM@EMNLP 2023, arXiv 2311.17295): Elo violates reliability and transitivity axioms on LLM data; sensitive to K-factor and match order — [arXiv abs](https://arxiv.org/abs/2311.17295).
- Bayesian Elo (Coulom) and Elo-uncertainty tooling exist for engine tournaments — [Bayesian Elo](https://www.remi-coulom.fr/Bayesian-Elo/). Chess-forum folklore that "30 games give 95% confidence" is not a primary source — [chess.com forum](https://www.chess.com/forum/view/off-topic/elo-rating-confidence-levels-based-on-number-of-games) (treat as unverified).
- For multiplayer free-for-all rating evaluation, NDCG is recommended as the metric for comparing rating systems on 100k+ FFA matches — [arXiv 2008.06787](https://arxiv.org/abs/2008.06787).

**Nash averaging, alpha-rank, Deviation Ratings, social-choice**

- Balduzzi, Tuyls, Perolat, Graepel, "Re-evaluating Evaluation" (NeurIPS 2018): "Elo is meaningless – it has no predictive power – in cyclic games like rock-paper-scissors"; Elo can be inflated by adding copies of weak agents; Nash averaging = maxent Nash of the antisymmetric meta-game; "Adding redundant copies of an agent ... should make no difference"; on Atari, "Human performance ties with the best agents, suggesting better-than-human performance has not yet been achieved"; "there is no harm (computational cost aside) from including all available tasks and agents" — [ar5iv](https://ar5iv.labs.arxiv.org/html/1806.02643); [NeurIPS PDF](http://papers.neurips.cc/paper/7588-re-evaluating-evaluation.pdf).
- alpha-Rank (Omidshafiei et al., Sci. Rep. 2019): ranking via evolutionary dynamics / Markov-Conley chains; "runs in polynomial time with respect to the total number of pure strategy profiles" while Nash for general-sum is intractable; handles >2 players and asymmetric games — [PMC](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6617105/).
- Deviation Ratings (Marris, Liu, Gemp, Piliouras, Lanctot, Feb 2025, arXiv 2502.11645): "the first N-player general-sum clone invariant rating", built on coarse correlated equilibria, applied "on several domains including LLMs evaluation" — [arXiv abs](https://arxiv.org/abs/2502.11645).
- VasE (Lanctot et al., arXiv 2312.03121): treats each task/game as a voter; maximal lotteries "satisfies important consistency properties ..., is computationally efficient ..., and identifies game-theoretic cycles"; "more robust than ... Elo and Nash averaging"; "predict outcomes better than Elo in a complex seven-player game" — [arXiv abs](https://arxiv.org/abs/2312.03121).
- Kaggle's Werewolf GTE (see KQ1) is the first production LLM leaderboard using an equilibrium-based, role-decomposed rating — [arXiv HTML 2609.31473](https://arxiv.org/html/2609.31473v1).

**Exploitability / NashConv**

- Lanctot et al. 2017 (PSRO): NashConv = "the sum of how much each player gains by deviating to their best response (unilaterally)", equal to exploitability in two-player zero-sum; used as the training-progress curve in Leduc poker — [NeurIPS 2017 PDF](https://proceedings.neurips.cc/paper/2017/file/3323fe11e9595c09af38fe67567a9394-Paper.pdf); [arXiv](https://arxiv.org/pdf/1711.00832).

**League / frozen-ladder evaluation and intransitivity**

- AlphaStar (Vinyals et al., Nature 2019): "new competitors were dynamically added to the league, by branching from existing competitors" while "original competitors are frozen"; 14 days, ~600 agents; final agent = Nash mixture of the league; human eval via Battle.net MMR >7000 — [DeepMind blog](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/). League exploiters' frozen copies are added "when they defeat all players in the league in more than 70% of games, or after a timeout of 2 x 10^9 steps", with 25% reset probability; evaluation = "round-robin tournament of all players throughout League training" plus a tournament "against held-out validation agents trained to follow specific human strategies"; "each point represents a past player, evaluated against the entire league and the elite built-in bot (whose Elo is set to 0)" — [Nature paper (unformatted PDF)](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf).
- Balduzzi et al. 2019, "Open-ended learning in symmetric zero-sum games" (ICML): **relative population performance** "v(P,Q) := p^T A_{P,Q} q" at a Nash (p,q) of the zero-sum game between populations; **effective diversity** "d(P) := p^T floor(A_P)_+ p" (rectified, Nash-weighted); PSRO_rN trains each agent against "the Nash-weighted mixture of agents that [they] beat or tie"; progress reported as v(P_t, reference) across iterations — [ar5iv](https://ar5iv.labs.arxiv.org/html/1901.08106); [arXiv abs](https://arxiv.org/abs/1901.08106).
- Czarnecki et al. 2020, "Real World Games Look Like Spinning Tops" (NeurIPS): Game of Skill = "(1) a strong transitive component" + "(2) diverse game styles with non-transitive interactions that diminish as skill increases"; **Nash clustering** = iteratively take the support of the maxent Nash, remove it, repeat; Proposition 3: convergence needs a population "not smaller than the size of the lowest layer occupied by at least one strategy"; empirically "for small population sizes, training does not converge and cycles for all games"; validated on Connect Four, Tic-Tac-Toe, Go (3x3, 4x4), Quake III, StarCraft II/AlphaStar, Disc, Elo, Blotto games — [ar5iv](https://ar5iv.labs.arxiv.org/html/2004.09468); [NeurIPS PDF](https://proceedings.neurips.cc/paper_files/paper/2020/file/ca172e964907a97d5ebd876bfdd4adbd-Paper.pdf).
- Sanjaya, Wang, Yang 2022, "Measuring the Non-Transitivity in Chess" (Algorithms 15(5):152): >1 billion Lichess/FICS games; non-transitivity quantified by "counting strategic cycles of length three" and "the size of Nash Clusters"; the "middle region of the transitive dimension is accompanied by a large degree of non-transitivity, which gradually diminishes" towards high Elo — [MDPI](https://doi.org/10.3390/a15050152); [arXiv](https://arxiv.org/pdf/2110.11737).
- Coevolution literature: "Without a guarantee of monotonic progress ... populations can 'forget' past strategies, resulting in cycling"; the Nash Memory (Ficici & Pollack 2003; Ficici 2004) "guarantees monotonicity"; IPCA/LAPCA archives (de Jong 2004) establish monotonic progress on test problems — [Bucci, GECCO 2007 coevolution tutorial](https://www.cs.york.ac.uk/rts/docs/GECCO_2007/docs/p3172.pdf); [Ficici & Pollack, "Monotonic solution concepts in coevolution" (GECCO 2005)](https://dl.acm.org/doi/10.1145/1068009.1068093); [A comparison of evaluation methods in coevolution](https://arxiv.org/pdf/1905.08723).

**Cross-play / zero-shot coordination / ad-hoc teamplay**

- Other-Play (Hu et al., ICML 2020): Hanabi self-play score vs cross-play with independently trained seeds: SAD 23.97 self-play but 2.52 cross-play; SAD+OP 23.93 self-play, 15.32 cross-play — [PMLR](https://proceedings.mlr.press/v119/hu20a.html); [arXiv](https://arxiv.org/pdf/2003.02979). ZSC = "the performance obtained by coordinating with other independently trained agents zero-shot".
- ZSC-Eval (NeurIPS 2024 D&B): evaluation partners generated via behaviour-preferring rewards, selected by **Best-Response Diversity (BR-Div)** (determinant of the similarity matrix of best responses), and scored with **Best-Response Proximity (BR-Prox)** = ego performance normalised by approximate best-response performance per partner; Overcooked used 20-30 evaluation partners x 5 seeds, GRF 6 partners x 3 seeds; Spearman correlation with human evaluation 0.90-1.00 — [ar5iv](https://ar5iv.labs.arxiv.org/html/2310.05208).
- Hanabi Challenge (Bard et al., AIJ 2020): the ad-hoc teamplay challenge evaluates "ability to play and coordinate with a wide range of teammates the agent has never encountered before"; "Good strategies are not unique" — [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S0004370219300116); few-shot revisit — [arXiv 2308.10284](https://arxiv.org/pdf/2308.10284).
- Melting Pot 2.0 scenario protocol (held-out background population; resident vs visitor; exploiter/random normalisation) — see KQ1 — [ar5iv](https://ar5iv.labs.arxiv.org/html/2211.13746).

### Inferences
- A "frozen ladder" for an LLM population = keep checkpoints of each generation's agents/strategy artifacts, run a cross-play matrix between the current population and every frozen generation, and report (a) relative population performance v(P_t, P_{t-k}) at Nash and (b) win rate vs a fixed anchor set (the AlphaStar "built-in bot Elo = 0" trick); Nash clustering on the same matrix tells you whether you are climbing the transitive axis or cycling.
- Because LLM populations will be small (tens of agents), Czarnecki's Proposition 3 implies the population must be at least as wide as the game's widest non-transitive layer; choosing games with thin mid-level cycles (or measuring them with Sanjaya-style 3-cycle counts) is a design lever.
- For cooperative games (teaching, shared conventions), the right scorer is cross-play against frozen past students/teachers (Other-Play) or BR-Prox vs a diverse partner set (ZSC-Eval), not self-play score.

### Gaps
- No source found giving a principled "games per rating" rule specific to LLM agents beyond Chatbot Arena's empirical sample counts and the TrueSkill/Glicko heuristics; Kaggle's 40 games/pair (chess) and GTBench's 50 matches are practice, not theory.
- Werewolf GTE / polarix has no standalone paper that I could locate; details are from the Game Arena report and Kaggle page summary.

## KQ3. Metrics for a POPULATION (best-of vs mean, area-under-curve vs compute, diversity, retention, transfer, cumulative/open-ended improvement)

### Takeaway
There is no single accepted "population improvement" number; the literature offers four families you can combine: (1) **Nash-weighted population value** (relative population performance; AlphaStar's Nash mixture = "best-of" that is robust to exploitation), (2) **mean/per-capita** returns (Melting Pot focal per-capita; cultural-evolution papers' average final resources), (3) **diversity** (effective diversity, QD coverage/QD-score, Nash-cluster count), and (4) **open-endedness/cumulative** curves (ANNECS; Hughes' novelty-and-learnability; OmniGameArena's IDC; OpenAI Five's TrueSkill-vs-compute).

### Cited Findings

- **Best-of vs mean**: AlphaStar selects the final agent from "the most effective mixture of strategies ... from the league's Nash distribution" (a Nash-weighted best-of) — [DeepMind blog](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/); Balduzzi 2019 defines population value as the Nash value v(P,Q) rather than the mean — [ar5iv](https://ar5iv.labs.arxiv.org/html/1901.08106). Melting Pot scores the *mean* over focal players ("focal-population per-capita return") — [ar5iv](https://ar5iv.labs.arxiv.org/html/2211.13746). Nash averaging explicitly downweights redundant agents so a population padded with clones cannot inflate its score — [ar5iv 1806.02643](https://ar5iv.labs.arxiv.org/html/1806.02643).
- **Diversity**: Balduzzi 2019 "effective diversity" d(P) = p^T floor(A_P)_+ p (only Nash-supported, mutually-beating agents count) — [ar5iv](https://ar5iv.labs.arxiv.org/html/1901.08106). Czarnecki's Nash clustering yields the number/size of non-transitive layers — [ar5iv 2004.09468](https://ar5iv.labs.arxiv.org/html/2004.09468). Quality-Diversity metrics: Coverage = "the number of non-empty cells ... in the archive"; QD-score = "the sum of the highest quality values found in each bin" — [IJCAI 2024 QD paper](https://www.ijcai.org/proceedings/2024/0773.pdf); [Pugh et al. 2016, Frontiers](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2016.00040/full). QD-through-AI-feedback applies these to LLM-generated artifacts — [arXiv 2310.13032](https://arxiv.org/pdf/2310.13032v4).
- **Cumulative / open-ended**: Enhanced POET's ANNECS = "Accumulated Number of Novel Environments Created and Solved"; an environment counts only if it passes a minimal criterion (neither too hard nor too easy against all agents so far) and is eventually solved; original POET "plateaus after around 20,000 iterations" whereas Enhanced POET's ANNECS keeps rising — [Enhanced POET, ICML 2020](https://proceedings.mlr.press/v119/wang20l/wang20l.pdf); [arXiv](https://arxiv.org/pdf/2003.08536). Hughes et al. 2024 (ICML oral): novelty = "∀t,∀T>t,∃T'>T: E[ℓ(t,T')] > E[ℓ(t,T)]" (artifacts become less predictable to an observer model fixed at time t); learnability = "∀T,∀t<T,∀T>t'>t: E[ℓ(t',T)] < E[ℓ(t,T)]" (more history lowers loss); open-ended iff both; "interestingness is represented ... by the observer's choice of loss function ℓ"; no numeric metric is proposed — [arXiv HTML](https://arxiv.org/html/2406.04268); [PMLR](https://proceedings.mlr.press/v235/hughes24a.html).
- **Improvement over rounds as a first-class metric**: OmniGameArena's Improvement Dynamics Curve reports per-round scores, time-to-peak and transfer to unseen variants instead of first-attempt scores — [arXiv 2606.09826](https://arxiv.org/html/2606.09826).
- **Skill vs compute curves**: OpenAI Five reached TrueSkill 254 after 770 +/- 50 PFlops/s-days; the TrueSkill-vs-compute curve had not plateaued at the end of training — [OpenAI Dota 2 paper](https://cdn.openai.com/dota-2.pdf); [arXiv 1912.06680](https://arxiv.org/pdf/1912.06680). AlphaStar reports Elo of past players evaluated against the entire league over training — [Nature PDF](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf).
- **LLM populations with transmissible written strategies** (closest published analogue to the startup's design): Vallinder & Hughes, "Cultural Evolution of Cooperation among LLM Agents" (arXiv 2412.10270; AAMAS 2025 EA): "12 agents in each generation", "10 generations", "top-performing 50% of agents (in terms of final resources) survive", new agents are prompted with "the strategies of surviving agents from the previous generation"; progress metric = "average final resources across all agents" per generation (max 30,720); "five runs for each LLM"; SEM shading, no formal tests, "sensitive dependence on initial conditions"; only Claude 3.5 Sonnet societies improved across generations — [arXiv HTML](https://arxiv.org/html/2412.10270); [AAMAS EA](https://www.ifaamas.org/Proceedings/aamas2025/pdfs/p2771.pdf). A 2026 cross-provider extension exists — [arXiv 2605.29874](https://arxiv.org/pdf/2605.29874) (not fetched).
- **Transfer as a population outcome**: SPIRAL (3 TextArena games -> up to +10% on 8 reasoning benchmarks, 7 OOD games) — [arXiv](https://arxiv.org/abs/2506.24119); lmgame-Bench (Sokoban RL -> Blocksworld >=10%, Tetris up to 8%, WebShop >=6%) — [arXiv HTML](https://arxiv.org/html/2505.15146).
- **Retention / forgetting**: AlphaStar's frozen league exists precisely so agents "continuously faced earlier strategy versions, avoiding the common problem of forgetting" — [DeepMind blog](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/); coevolution archives (Nash memory, IPCA) guarantee monotonic progress against the archive — [GECCO tutorial](https://www.cs.york.ac.uk/rts/docs/GECCO_2007/docs/p3172.pdf).

### Inferences
- A defensible composite for "is the population improving" across 2-3 games: per game, (i) relative population performance vs each frozen generation (Nash value), (ii) BT-Elo of the population's Nash mixture vs a fixed anchor ladder (random, MCTS-1000, Stockfish level k, frozen gen-0), (iii) effective diversity / Nash-cluster count, (iv) ANNECS-style count of "new strategies that beat the archive and are later retained"; then aggregate across games with Nash averaging or VasE rather than the arithmetic mean so that no single game dominates.
- "Credit for students' improvement" has no published metric; the nearest building blocks are relative population performance deltas between generations (Balduzzi) and the cultural-evolution protocol (surviving strategies carried forward), so this will have to be defined in-house.

### Gaps
- No paper found that defines an "area under the improvement curve vs compute" metric for *agent populations*; AUC-type reporting appears only informally (TrueSkill vs PFlops-days curves). Flag as a gap to define yourself.
- No paper found that credits teachers for student improvement in LLM populations.

## KQ4. Statistical practice (seeds, bootstrap, learning curves)

### Takeaway
Credible practice is: >=10 independent runs per condition with stratified bootstrap CIs on the IQM (Agarwal et al.), or Bradley-Terry with bootstrap CIs over the match log for pairwise data (Chatbot Arena, GameBench B=10,000); many LLM-game papers fall well short (3-5 runs, 10 games per matchup), which is a comparability hazard, not a standard to copy. Kaggle's 40 games/pair (chess) and 20,000 hands/pair (poker) are the most rigorous published LLM-game sample sizes.

### Cited Findings

- Agarwal et al. 2021, "Deep RL at the Edge of the Statistical Precipice" (NeurIPS): "5 or less runs are common in the field"; "percentile CIs provide good interval estimates for as few as N=10 runs for both median and IQM scores", while median needs ~50-100 runs on Atari 100k; IQM "discards the bottom and top 25% of the runs and calculates the mean score of the remaining 50%"; stratified bootstrap = "re-sample runs with replacement independently for each task"; also performance profiles and "average probability of improvement"; bias in sample medians was "about 36% of its mean improvement" in one case — [ar5iv](https://ar5iv.labs.arxiv.org/html/2108.13264); [rliable explainer](https://araffin.github.io/post/rliable/).
- Sample sizes used by the LLM-game suites: Kaggle chess 40 games/pair, poker 20,000 hands/pair (block bootstrap CIs), Werewolf ~31,500 games — [arXiv 2609.31473](https://arxiv.org/html/2609.31473v1); GTBench 50 matches/competition with first-move alternation — [arXiv 2402.12348](https://arxiv.org/html/2402.12348); GameBench BT + 10,000 bootstrap resamples, uneven sampling — [arXiv 2406.06613](https://arxiv.org/html/2406.06613v1); Werewolf Arena 10 games/matchup — [arXiv 2407.13943](https://arxiv.org/html/2407.13943v1); SPIN-Bench 10 games (4 for chess) — [arXiv 2503.12349](https://arxiv.org/html/2503.12349v1); BALROG 25/10/20/5 seeds by env, reports +/- SE — [arXiv 2411.13543](https://arxiv.org/html/2411.13543); lmgame-Bench 3 runs (some 1) — [arXiv 2505.15146](https://arxiv.org/html/2505.15146); Orak 3-20 trials — [arXiv 2506.03610](https://arxiv.org/html/2506.03610v3); GAMA-Bench 5 runs, prompt-rephrasing variance up to 23.7 points — [arXiv 2403.11807](https://arxiv.org/html/2403.11807); clembench 250 instances — [ar5iv 2305.13455](https://ar5iv.labs.arxiv.org/html/2305.13455); Vallinder & Hughes 5 runs x 10 generations x 12 agents, SEM only — [arXiv 2412.10270](https://arxiv.org/html/2412.10270); ZSC-Eval 20-30 partners x 5 seeds — [ar5iv 2310.05208](https://ar5iv.labs.arxiv.org/html/2310.05208); Chatbot Arena 1000-resample multinomial bootstrap / sandwich SEs — [arXiv 2403.04132](https://arxiv.org/html/2403.04132).
- Elo is order-sensitive and unstable even over >>1,000 match permutations; BT or Glicko recommended — [arXiv 2411.14483](https://arxiv.org/html/2411.14483).
- TrueSkill needs ~3-12 games/player (FFA) to ~46-91 (large teams), up to 3x more in practice — [Microsoft Research](https://www.microsoft.com/en-us/research/project/trueskill-ranking-system/).
- Prompt sensitivity is a major variance source in LLM games (GAMA-Bench; lmgame-Bench's stated motivation "brittle vision perception, prompt sensitivity, and potential data contamination") — [arXiv 2403.11807](https://arxiv.org/html/2403.11807); [arXiv 2505.15146](https://arxiv.org/abs/2505.15146).

### Inferences
- Unit of analysis for a population experiment should be the *population run* (seed), not the game: with 5 seeds per condition (the cultural-evolution precedent) you cannot get tight CIs; aim for >=10 population seeds per condition and bootstrap over seeds, with within-seed game counts set by the rating method (>=40 colour-balanced games per pair for BT).
- Report learning curves vs compute (LLM tokens or dollars) with stratified-bootstrap bands, plus a performance profile across games, rather than a single aggregate.

### Gaps
- No LLM-population paper found that uses >=10 seeds with bootstrap CIs; the "credible" standard here is borrowed from deep-RL (rliable) and from Kaggle's single-agent arenas.

## KQ5. Games common across multiple suites with fast simulators

### Takeaway
The classical OpenSpiel games — **Tic-Tac-Toe, Connect Four, Kuhn/Leduc Poker, Liar's Dice, Negotiation, Iterated Prisoner's Dilemma, Nim, Pig, Breakthrough, Blind Auction** — are the most comparable choice: all ten GTBench games are also in TextArena, several are in SPIN-Bench and Board Game Arena, and OpenSpiel/Pgx give solver references and GPU-speed simulation. **Chess, Poker and Werewolf** add comparability with Kaggle Game Arena; **Hanabi/Overcooked** are the standard cooperative/ZSC testbeds with JAX simulators at 10^6-10^7 steps/s.

### Cited Findings

Cross-suite overlap (each membership sourced in KQ1):
- **Tic-Tac-Toe**: TextArena (+Ultimate/Reverse/Wild/Quantum/3-player variants) — [envs README](https://github.com/LeonGuertler/TextArena/blob/main/textarena/envs/README.md); GTBench — [arXiv](https://arxiv.org/html/2402.12348); SPIN-Bench — [arXiv](https://arxiv.org/html/2503.12349v1); Board Game Arena — [arXiv](https://arxiv.org/html/2508.03368v1); SPIRAL training — [arXiv](https://arxiv.org/abs/2506.24119); Czarnecki 2020 — [ar5iv](https://ar5iv.labs.arxiv.org/html/2004.09468); TTT-Bench — [arXiv](https://arxiv.org/pdf/2506.10209).

- **Kuhn Poker**: TextArena; GTBench; Board Game Arena; SPIRAL. **Leduc Hold'em**: TextArena; PSRO/NashConv reference domain — [NeurIPS 2017](https://proceedings.neurips.cc/paper/2017/file/3323fe11e9595c09af38fe67567a9394-Paper.pdf). **Poker (multi-player NLHE-style)**: TextArena Poker (2-15); Kaggle Game Arena — [arXiv 2609.31473](https://arxiv.org/html/2609.31473v1).

Not found in TextArena's catalogue.

Fast simulators:
- **OpenSpiel**: "70+ environments", C++ core with Python bindings; underlying engine for GTBench and Board Game Arena — [OpenEnv page](https://meta-pytorch.org/OpenEnv/environments/openspiel.html); [arXiv 1908.09453](https://arxiv.org/pdf/1908.09453).
- **Pgx** (JAX, NeurIPS 2023): "10-100x faster than existing implementations available in Python"; "10x faster in complex game simulations like Backgammon and Go ... on a single A100"; compared against PettingZoo and OpenSpiel — [arXiv 2303.17503](https://arxiv.org/abs/2303.17503); [OpenReview](https://openreview.net/pdf?id=UvX8QfhfUx).

- **Craftax** (JAX): 267,000 steps/s, "169x faster" than Crafter; Craftax-Classic 257x — [arXiv 2402.16801](https://arxiv.org/pdf/2402.16801v2). **NetHack Learning Environment**: "14.4k steps per second on an Intel Core i7 2.9 GHz CPU" — [arXiv 2006.13760](https://arxiv.org/pdf/2006.13760).
- **Kaggle Game Arena** scale is the practical ceiling for LLM-driven play: 900,000 poker hands and ~31,500 Werewolf games across 10 models — [arXiv 2609.31473](https://arxiv.org/html/2609.31473v1).

### Inferences
- Maximum-comparability picks: (1) a classical perfect-information game present in TextArena + GTBench + SPIN-Bench + Board Game Arena + OpenSpiel/Pgx — Connect Four (or Tic-Tac-Toe if you want a solved anchor); (2) an imperfect-information game with equilibrium references — Kuhn/Leduc Poker (OpenSpiel CFR, NashConv computable) with heads-up poker as the Kaggle-comparable scale-up; (3) a cooperative/communication game — Hanabi (ZSC/cross-play literature, JaxMARL speed, SPIN-Bench numbers) or Negotiation (TextArena + GTBench + SPIRAL).
- For LLM agents the simulator is rarely the bottleneck (inference is), but a JAX/C++ engine matters once you add RL fine-tuning, exploitability computation, or large frozen-ladder cross-play matrices (e.g., 10 generations x 12 agents x 40 games/pair).

### Gaps
- Could not verify Pgx's full game list from the fetched sources (paper names Backgammon, Shogi, Go; the repo lists more); and whether OpenSpiel contains every GTBench game beyond GTBench's own statement.
- TextArena does not appear to include Hanabi; a TextArena-only stack therefore lacks the canonical cooperative game.
