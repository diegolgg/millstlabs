# Program-as-strategy games and simulators for LLM-population sandboxes (status as of Oct 2026)

Scope: candidates where an agent's strategy is a PROGRAM evaluated by a fast deterministic simulator, assessed against the startup's five criteria (API, long runs / sim speed, published baselines incl. LLM/evolution, rigorous non-game-specific metric, visual replay). Anything taken only from a search snippet rather than a fetched primary page is marked "(snippet; unverified)".

## KQ1. OpenSpiel: exact exploitability games/sizes, speed, LLM-written-policy work, Elo/alpha-rank tools

### Takeaway
OpenSpiel is the only candidate with an ABSOLUTE metric (tabular exploitability/NashConv) and it is now the substrate for two DeepMind papers (Feb and Sep 2026) in which AlphaEvolve-driven LLMs evolve C++ game-playing / equilibrium-finding code evaluated by exploitability and alpha-rank/SCO; exploitability is exact only for enumerable games (Kuhn 12 infosets, Leduc 288, 1-die Liar's Dice 24,576, small Goofspiel), and I found no published games-per-second figure for the C++ core.

### Cited Findings
- OpenSpiel 2.0 was released July 14, 2026, adds typed, JSON-interchangeable state/action/observation structs so game states can be sent "to a frontend, an LLM, or a database", claims "over 120 games" (19 new incl. Shogi, Xiangqi, Crazyhouse, social deduction), adds Windows pip install, and states "Much of the design of OpenSpiel 2.0 was inspired by Kaggle Game Arena use cases, such as language models interacting with game environments" — [Introducing OpenSpiel 2.0 (Lanctot)](https://mlanctot.info/introducing_open_spiel_2.0/). The readthedocs games page lists roughly 180 entries (count conflicts with the "120+" blog figure; the docs list likely includes variants) — [OpenSpiel games list](https://openspiel.readthedocs.io/en/latest/games.html).
- Games relevant here and their test status: kuhn_poker, leduc_poker, liars_dice, goofspiel, universal_poker (ACPC), connect_four, chess, go, hanabi, dots_and_boxes are all "thoroughly tested"; dark_hex and battleship are "implemented but lightly tested"; othello is not listed — [OpenSpiel games list](https://openspiel.readthedocs.io/en/latest/games.html).
- Algorithms/analysis tools shipped and marked thoroughly tested: "Exploitability / Best response | Tabular", "α-Rank | Eval./Viz.", "Voting-as-Evaluation (VasE) | Eval./Viz. | Lanctot et al. '23", CFR, CFR-BR, external/outcome-sampling MCCFR, RCFR, PSRO, MCTS, AlphaZero (C++/LibTorch and Python/TF) — [OpenSpiel algorithms](https://openspiel.readthedocs.io/en/latest/algorithms.html). No separate "Elo" tool is listed on that page — [OpenSpiel algorithms](https://openspiel.readthedocs.io/en/latest/algorithms.html).
- Soft Condorcet Optimization (SCO), the rating used in the 2026 DeepMind evolution papers, is from Lanctot et al., AAMAS 2025 (arXiv 2411.00119): an MLE ranking under a noisy-ground-truth-ranking model; "SCO ratings are maximal for Condorcet winners when they exist, which is not necessarily true for ... Elo"; validated on 52,958 Diplomacy players / 31,049 games — [SCO paper (AAMAS 2025)](https://www.ifaamas.org/Proceedings/aamas2025/pdfs/p1253.pdf).
- Game sizes where exact tabular exploitability is routine: Kuhn poker has 12 information sets; Leduc Hold'em 288; the standard 1-die Liar's Dice benchmark 24,576; CFR+ reaches ~9e-4 (Kuhn) and ~1.5e-3 (Leduc) exploitability — (snippet; unverified) [search aggregate incl. ALA2020 approximate exploitability paper](https://ala2020.vub.ac.be/papers/ALA2020_paper_43.pdf). Exploitability = NashConv/n where NashConv is the sum of individual deviation incentives — [Approximate Exploitability (arXiv 2004.09677)](https://arxiv.org/pdf/2004.09677).
- LLM-evolved code on OpenSpiel #1: "Discovering Multiagent Learning Algorithms with Large Language Models" (Li, Schultz, Hennes, Lanctot, DeepMind, Feb 21 2026) uses AlphaEvolve to treat algorithm source as an evolvable genome; discovered VAD-CFR and SHOR-PSRO; training domains 3-player Kuhn, 2-player Leduc, 4-card Goofspiel, 5-sided Liar's Dice; metric = exploitability; VAD-CFR matched/beat SOTA in 10 of 11 games with exploitability below 1e-3, SHOR-PSRO beat baselines in 8 of 11 — [alphaXiv 2602.16928](https://www.alphaxiv.org/abs/2602.16928v2).
- LLM-evolved code on OpenSpiel #2: "Modular Discovery of General Game-Playing Algorithms with LLMs" (Li, Schultz, Lanctot, Hennes, DeepMind, Sep 27 2026, arXiv 2609.33115): AlphaEvolve with Gemini 3.5 Flash mutates C++ MCTS mechanisms + per-game heuristics; trained on 50 OpenSpiel games; evaluation at a fixed budget of 50 ms wall-clock per decision (4 threads) or 1,000 simulations; metrics = AlphaRank stationary distributions, SCO ratings in [0,1000], pairwise win rates, and exploitability for Kuhn/Leduc/Liar's Dice; results: SCO 509.34±0.39 vs PUCT 503.92±1.43, 65.2%±1.7% win vs PUCT, 83.3% vs Max-Backup; held-out 19 games 62.2–92.7% vs baselines; 360 synthesized games 70.4% vs PUCT; 10–20x simulation-efficiency gains on exploitability in Kuhn/Leduc/Liar's Dice; weak vs specialist engines (≤7% vs Stockfish, ≤10% vs KataGo 9x9, 32–41% vs Egaroucid Othello); includes anti-cheating gates, code-complexity bounds, "stochastic quorum scheduling" to control evaluation noise — [arXiv 2609.33115](https://arxiv.org/html/2609.33115).
- LLMs acting (not writing programs) on OpenSpiel: Game Reasoning Arena (arXiv 2508.03368) is a library for evaluating LLM decision-making on OpenSpiel board games vs other agents — (snippet; unverified) [arXiv 2508.03368](https://arxiv.org/html/2508.03368v3). Kaggle Game Arena (DeepMind/Kaggle, Sep 25 2026 paper) uses chess, heads-up poker and 8-player Werewolf; LLMs return actions from text states; chess rated by Elo, poker by BB/100 with "each pair plays 20,000 hands: 10,000 deals played twice" with seats/cards swapped; bootstrap CIs; GPT-5.2 leads poker at 46.56 BB/100; harness open-sourced with trajectories on Kaggle — [Game Arena paper (alphaXiv 2609.31473)](https://www.alphaxiv.org/abs/2609.31473). The Aug 5–7 2025 chess exhibition was won by o3 over Grok 4; leaderboard built from "approximately 100 matches per model pairing" — [Chess.com day 3](https://www.chess.com/news/view/kaggle-game-arena-chess-2025-day-3).
- "Evaluating LLMs in Open-Source Games" (Sistla et al., Dec 2025) is the closest thing to "programs as strategies" for LLMs: players submit Python programs that receive the opponent's source code and output actions in 10-round Iterated Prisoner's Dilemma and the Coin Game; 10 meta-rounds of rewriting; evaluated by payoff, strategic-feature analysis and replicator dynamics; o4-mini 88% accuracy on the SPARC code-reading benchmark; does NOT use OpenSpiel (custom sim + Axelrod library); code "open-sourced upon acceptance" — [arXiv 2512.00371](https://arxiv.org/html/2512.00371v1).
- Speed: OpenSpiel games/utilities are C++ with pybind11 bindings — [OpenSpiel intro](https://openspiel.readthedocs.io/en/latest/intro.html); the Modular Discovery paper's budget of 50 ms/decision with 1,000 simulations implies ~20k MCTS simulations/s on its small-to-mid games — [arXiv 2609.33115](https://arxiv.org/html/2609.33115).

### Inferences
- For an apples-to-apples SOTA comparison with LLM program evolution, OpenSpiel's small imperfect-information games are the strongest option today: two 2026 DeepMind papers publish exploitability numbers (<1e-3) and SCO/AlphaRank protocols that a population run could reproduce directly.
- Exact exploitability caps the game size (hundreds to tens of thousands of infosets); for anything larger (limit hold'em abstractions, ACPC universal_poker, Goofspiel 13) you fall back to approximate exploitability (learned best response) or to Elo/alpha-rank, i.e. a relative metric.
- Small OpenSpiel games are not visual; "why population A is better" would have to be shown via policy tables / exploitability-by-infoset rather than a replay.

### Gaps
- No published games-per-second benchmark for OpenSpiel's C++ core or Python overhead was found (searches returned only generic pybind11 overhead numbers).
- I could not fetch the Kaggle Game Arena landing page (JS-only); exact current game roster beyond chess/poker/werewolf (e.g., Go) is unverified.
- Exact infoset counts come from a search snippet, not a fetched primary table; the OpenSpiel paper's size table (arXiv 1908.09453) would be the primary source.

## KQ2. Bot-league games: maintained engines, reference bots, speed, visualizers, LLM-bot work

### Takeaway
Lux AI S3 (JAX, 24x24 map, 100-step matches, best-of-5) and Generals.io (JAX sim at 50.7M steps/s on one H200, superhuman RL bot, human ladder) are the fastest and best-anchored bot-league games; CodeClash (Nov 2025) is the key LLM-writes-the-bot baseline across Battlesnake/Halite/Robocode/Core War/RobotRumble/Battlecode (Elo, 1,000 sims per round, frontier LLMs lose every round to expert humans), and Softmax (Metta-AI) already runs 154+ live leagues incl. a Battlecode 2026 port and Generals — a near-identical sandbox concept.

### Cited Findings
- Lux AI Season 3 (NeurIPS 2024 competition; Kaggle; $50k prize; entry deadline Mar 3 2025): 1v1, partial observability, best-of-5 with randomized game parameters for meta-learning; "GPU parallelized game environment via jax" — [NeurIPS 2024 competition page](https://neurips.cc/virtual/2024/competition/84798); [Lux-Design-S3 GitHub](https://github.com/Lux-AI-Challenge/Lux-Design-S3/). Specs: 24x24 randomly generated grid; matches last 100 timesteps; 5 matches per game with map persisting across matches; fog of war; per-game randomized move cost, sensor range, sap cost/range, nebula effects; win = most matches, match tiebreak by relic points then unit energy — [Lux S3 specs](https://github.com/Lux-AI-Challenge/Lux-Design-S3/blob/main/docs/specs.md). Bot kits in Python and JavaScript; replay viewer at https://s3vis.lux-ai.org/ (upload replay.json) — [Lux-Design-S3 GitHub](https://github.com/Lux-AI-Challenge/Lux-Design-S3/). Throughput claim "100k-1M+ FPS" on GPU/TPU with benchmark script `src/tests/benchmark_env.py -n 16384 -t 5` — (snippet; unverified) [Kaggle discussion 551464](https://www.kaggle.com/competitions/lux-ai-season-3/discussion/551464). For scale, the S2 JAX engine JUX reported 363k steps/s on an A100-40GB at batch 20k with 100 units, 136k steps/s at 1,000 units — (snippet; unverified) [RoboEden/jux](https://github.com/RoboEden/jux).
- Lux S3 results: 1st place "Flat Neurons" used IMPALA with ResNet+ConvLSTM+Transformer, ~200M params, 3–4 days on 8xH100, self-play mixing current and older versions (prioritized fictitious self-play); 2nd "Frog Parade" PPO, 300M params x2, rewrote the engine in Rust (~10,800 lines) to remove the sim bottleneck; top rule-based entry placed 20th; gold medals dominated by RL/IL — [zenn.dev summary of S3 writeups](https://zenn.dev/kurupical/articles/61dbeedf89a29d). 14th place (3Comets) trained 15 days on one RTX 4090, ~30M updates, >1B env steps — [Kaggle writeup](https://www.kaggle.com/competitions/lux-ai-season-3/writeups/3comets-multi-agent-rl-silver-solution-by-3comets-). Lux S1 had 22,000+ submissions from 1,100+ teams — [lux-ai.org](https://www.lux-ai.org/).
- Generals.io: strakam/generals-bots is a PettingZoo/Gymnasium-compliant simulator; a JAX-native version reaches "50.7M environment steps per second on a single H200 GPU" — [Superhuman AI for Generals.io (arXiv 2606.23348, Jun 22 2026)](https://arxiv.org/html/2606.23348v1); [strakam/generals-bots](https://github.com/strakam/generals-bots). The transformer PPO self-play agent (4 days on 16 H200s) reached #1 on the public 1v1 ladder with 118 OpenSkill points, 199–70 across 269 games vs the top two humans, 20–0 vs prior bots; agent code open (CC BY 4.0) — [arXiv 2606.23348](https://arxiv.org/html/2606.23348v1). An earlier NumPy env + PPO reached top-25 on the 1v1 leaderboard — (snippet; unverified) [arXiv 2507.06825](https://arxiv.org/pdf/2507.06825). Softmax runs a "Generals Competition" league with docs at generals.bot — [generals.bot docs](https://www.generals.bot/docs).
- Battlecode: MIT's competition, "two teams of virtual robots ... managing resources", prize pool >$20k, registration open for 2026 — [battlecode.org](https://battlecode.org). 2025 scaffold has Java and Python engines — [battlecode25-scaffold](https://github.com/battlecode/battlecode25-scaffold). Softmax/Metta-AI ported Battlecode 2026 to its platform: original Java 21 engine + both players in one JVM container, source-ZIP submissions, "two-seat team_pair schedule so each pair plays both side assignments, Elo ranking", seven archived 2026 bots under platform-owned identities, replays via the original browser client — [Metta-AI/coworld-battlecode-2026](https://github.com/Metta-AI/coworld-battlecode-2026).
- Softmax (Metta-AI) platform: "league and tournament APIs — standings, scheduling, submissions, all scriptable"; 154+ games as live leagues with "team win/loss MMR with rating-based matchmaking"; four-step loop "pair with a coding agent, code competing players, learn from games ..., climb ranks"; also an LLM-agent board game Cogherence (3–6 LLM agents, territory+economy+cheap talk) and a "coworld-builder" managed agent that takes an idea to a live league — [softmax.com](https://softmax.com); [Metta-AI org](https://github.com/metta-ai); [coworld-cogherence](https://github.com/Metta-AI/coworld-cogherence); [coworld-builder](https://github.com/Metta-AI/coworld-builder).
- CodeClash (Yang, Lieret, Jimenez, Press, Schmidt, D. Yang; Nov 2 2025): LM systems iteratively edit codebases that compete in 7 arenas — Battlesnake, Core War, Halite, no-limit Hold'em poker, RoboCode, RobotRumble, MIT Battlecode 2025; 15 rounds per tournament, 1,000 simulations per round, 10 tournaments per model pair per arena, 1,680 tournaments / 25,200 rounds, "2.4 million hours of runtime"; Elo by MLE with 98% pairwise-order agreement under bootstrap; Claude Sonnet 4.5 Elo 1389, GPT-5 1360, o3 1343; Sonnet 4.5 69.9% avg win rate; "top models lose every round against expert human programmers"; ungrounded edits in >65% of rounds; codebases bloat ~linearly in rounds; code at github.com/CodeClash-ai/CodeClash, viewer at codeclash.ai — [arXiv 2511.00839](https://arxiv.org/html/2511.00839v1).
- Halite: created by Two Sigma with Cornell Tech; Halite III repo (MIT license, 9,558 commits) contains game_engine, apiserver, starter_kits, website, tools, and a libhaliteviz visualizer — [HaliteChallenge/Halite-III](https://github.com/HaliteChallenge/Halite-III); [Wikipedia](https://en.wikipedia.org/wiki/Halite_AI_Programming_Competition); community Electron replay viewer "Fluorine" — [fohristiwhirl/fluorine](https://github.com/fohristiwhirl/fluorine).
- Battlesnake: rules/engine is a Go module with a CLI (`battlesnake play -W 11 -H 11 --url ...`), snakes are HTTP services, modes standard/solo/royale/constrictor/wrapped, `/board` directory for visualization — [BattlesnakeOfficial/rules](https://github.com/BattlesnakeOfficial/rules).
- Robocode Tank Royale: Python Bot API 1.4.0 released Oct 1 2026, bots connect by WebSocket to ws://localhost:7654, GUI acts as server/launcher — [PyPI robocode-tank-royale](https://pypi.org/project/robocode-tank-royale/).
- Screeps: open-source standalone server (Node.js 22 LTS, ISC license, JavaScript bots, private servers, LokiJS/Mongo/Redis storage, CLI on port 21026), repo active (273 commits, 49 open issues) — [screeps/screeps](https://github.com/screeps/screeps).
- MicroRTS-Py (Gym-μRTS): Python over a Java engine; reference bots RandomBiasedAI, WorkerRushAI, LightRushAI, CoacAI; TrueSkill evaluation with iterative matching; FFmpeg video recording; "officially deprecated August 11, 2025, due to limited community adoption" — [Farama-Foundation/MicroRTS-Py](https://github.com/Farama-Foundation/MicroRTS-Py). Best DRL bot beat every past μRTS competition bot on a single map after ~60 h on 1 GPU/3 vCPU — [arXiv 2105.13807](https://arxiv.org/abs/2105.13807).
- Pommerman: NeurIPS 2018 2v2 competition; I found no evidence of maintenance after 2019 — [arXiv 1809.07124](https://arxiv.org/abs/1809.07124); [MultiAgentLearning/playground](https://github.com/MultiAgentLearning/playground/tree/NeurIPS-2018-Docker-Agents).
- Connect Four as an LLM-coding target: "Frontier Coding Agents Can Now Implement an AlphaZero Self-Play Pipeline for Connect Four" (Apr 27 2026): Claude Opus 4.7, GPT-5.4 and two others given a 3-hour consumer-hardware budget; round-robin anchored to the Pascal Pons perfect solver; Opus 4.7 won as first mover in 7 of 8 trials vs Pons, others ≤2; authors say the task went from infeasible (Jan 2026) to "near-saturation" — [arXiv 2604.25067](https://arxiv.org/abs/2604.25067).

### Inferences
- Only Lux S3 and Generals.io among bot-league games have accelerator-native simulators (10^5–10^7 steps/s); Battlecode/Halite/Battlesnake/Robocode run at JVM/Go/HTTP speeds suited to thousands, not millions, of games per hour — CodeClash's 2.4M runtime-hours for 25,200 rounds (~95 h per round of 1,000 sims across 7 arenas) is a realistic cost anchor.
- CodeClash is the most directly comparable published baseline for "LLM writes the bot": it supplies Elo numbers, a 1,000-sim-per-round protocol and a public leaderboard, but it is a single-codebase-per-model setup with no population/teaching structure, so a population method would have a clean, uncontested comparison.
- Softmax's coworlds are a live competitor for the exact infrastructure (leagues, MMR, replays, coding-agent loop); the differentiator would have to be the population/teaching/credit mechanism, not the platform.
- Lux S3 and Generals.io have only RELATIVE metrics (Kaggle rating / OpenSkill ladder); Generals.io gets a human anchor via the public ladder, Lux does not post-competition.

### Gaps
- Lux S3 GPU throughput number (100k–1M+ FPS) and JUX numbers come from snippets; the OpenReview proposal was blocked by a verification page and Kaggle pages are JS-only.
- No paper or competition specifically about LLM-written Lux bots was found; Kaggle Game Arena does not cover Lux.
- Participant counts for Lux S3 and Battlecode 2026 not found.

## KQ3. Neural MMO 2.0 / Melting Pot / Craftax-MA: population size, episode length, speed, built-in evaluation, LLM work, renderers, resource competition

### Takeaway
Neural MMO 2.0 (128 agents default, up to 1,024; ~3,000 agent-steps/core/s; web client; task-completion scoring) and Melting Pot 2.0 (50+ substrates, 256+ scenarios, 2–16 players, min-max normalized score vs trained exploiters) are the persistent-world options; both score via task/return metrics that are game-specific, neither has LLM-program-evolution baselines, and Craftax-MA (JAX, 250M steps in <1 h on one L40S) is far faster but cooperative-only.

### Cited Findings
- Neural MMO 2.0 (NeurIPS 2023 D&B; Suárez et al.): "128 agents in the standard setting and support for up to 1024"; complete rewrite with 3x performance; CleanRL/PufferLib baseline; web client at neuralmmo.github.io/client — [arXiv 2311.03736](https://arxiv.org/abs/2311.03736). Engine "runs at approximately 3,000 agent steps per CPU core per second, up from approximately 800 to 1,000"; one action = 0.6 s game time so one core simulates 5,000x real-time per agent, "equivalent to 250M agent steps or roughly 2.5 terabytes of data per day at approximately 10 KB per observation"; individual models trainable in 8 A100-hours; 5 gathering + 3 combat professions, scripted NPCs, global market for item trade; task system (GameState/Predicates/Tasks) with per-agent or team tasks — [NMMO 2.0 paper PDF](https://proceedings.neurips.cc/paper_files/paper/2023/file/9ca22870ae0ba55ee50ce3e2d269e5de-Paper-Datasets_and_Benchmarks.pdf). The NeurIPS 2023 competition scored teams of 8 agents among 128 on tasks completed vs the other 118 agents — [same PDF](https://proceedings.neurips.cc/paper_files/paper/2023/file/9ca22870ae0ba55ee50ce3e2d269e5de-Paper-Datasets_and_Benchmarks.pdf); results paper at [arXiv 2508.12524](https://arxiv.org/pdf/2508.12524). Experiments use "up to 128 agents on 128x128 maps with 1024-step horizons" — (snippet; unverified) [arXiv 2311.03736](https://arxiv.org/abs/2311.03736).
- Melting Pot 2.0 (DeepMind): "over 50 multi-agent reinforcement learning substrates ... and over 250 unique test scenarios" (GitHub says 256+); scenarios pair a substrate with a held-out "background population"; primary metric = focal-population per-capita return; "resident" vs "visitor" modes; results min-max normalized between a uniform-random agent (lower bound) and "exploiters" (ACB/OPRE agents trained directly on each test scenario for 1e9 steps, upper bound); background bots are "puppet bots" (hierarchical scripted-goal policies, e.g., a Clean Up bot that only cleans if others clean); episodes in e.g. Boat Race last 2000 steps; resource-competition substrates include Clean Up, Commons Harvest (Open/Closed/Partnership), Factory of the Commons, Territory, Chemistry — [arXiv 2211.13746 PDF](https://arxiv.org/pdf/2211.13746); [google-deepmind/meltingpot](https://github.com/google-deepmind/meltingpot). Players per substrate range 2–16, most ~8 — (snippet; unverified) [DeepMind blog](https://deepmind.google/blog/melting-pot-an-evaluation-suite-for-multi-agent-reinforcement-learning/). Release notes mention "x2 speed improvement to some substrates" — (snippet; unverified) [meltingpot releases](https://github.com/google-deepmind/meltingpot/releases).
- Craftax-MA / Craftax-Coop (Al Omari, Matthews, Rutherford, Foerster; Nov 2025): JAX, "a training run using 250 million environment interactions completing in under an hour" (IPPO, 4 agents, single L40S); throughput 10^3–10^5 steps/s scaling log-log-linearly to 1,024 parallel envs; "environment can support an unbounded number of agents"; Craftax-Coop has 3 specialized roles (Miner/Forager/Warrior) with trading; shared reward (fully cooperative); MAPPO stagnates at ~1B steps (+2% over the next 4B); JaxMARL interface; code github.com/BaselOmari/MA-Craftax — [arXiv 2511.04904 PDF](https://arxiv.org/pdf/2511.04904).
- LLM work on these worlds: ALEM (Tessera et al., Jun 6 2026) is "a JAX-based benchmark for open-ended multi-agent coordination built on Craftax-like dynamics" (not Melting Pot) with exploration/crafting/trading/combat; 13 LLMs zero-shot in homogeneous teams average only ~6% normalized return — [arXiv 2606.08340](https://arxiv.org/abs/2606.08340). I found no paper using LLM agents or LLM-written programs on Neural MMO 2.0 or Melting Pot 2.0 (searches returned only LLM-population social-convention and persona papers).

### Inferences
- For "groups competing for finite resources", NMMO (128 agents, market, NPCs, procedurally regenerated resources) and Melting Pot's commons substrates fit the narrative best, but their metrics (task completion; normalized focal return) are game-specific and relative to trained baselines, not absolute, and there is no LLM-evolution baseline to compare against.
- NMMO at ~3k agent-steps/core/s means one 128-agent, 1,024-step episode costs ~44 core-seconds; thousands of generations with hundreds of episodes each is feasible on a few dozen cores but slow relative to JAX games.
- Melting Pot's exploiter-normalized score is the most principled of the three for cross-substrate aggregation, but exploiters cost 1e9 training steps each to regenerate if the population changes the substrate.

### Gaps
- No steps-per-second figure for Melting Pot 2.0 found in the paper or README.
- NMMO's 128x128 map / 1024-step horizon came from a search snippet rather than the fetched PDF text.
- No LLM-program-evolution results exist on any of these three worlds.

## KQ4. Pokémon Showdown: PokéLLMon, PokéChamp, PokéAgent/Metamon results; API; cost; meta drift; team-building artifact

### Takeaway
Showdown gives a human-ladder anchor (PokéChamp ~1300–1500 Elo, Metamon top-10% of active players) and a maintained open benchmark (PokéAgent Challenge, FH-BT/Glicko-1/GXE over 1.6M+ agent matches) but every strong LLM agent calls the LLM at inference per turn, the RL/search bots beat LLM agents, and sim speed is ~10 random-battle games/s on a local server.

### Cited Findings
- PokéLLMon (GPT-4, gen8randombattle, poke-env): 48.57% win rate on the ladder over 105 battles, 56.00% in 50 invited battles; vs heuristic bot 26% baseline → 58% with ICRL + knowledge augmentation + consistent action generation; no cost/latency reported — [arXiv 2402.01118](https://arxiv.org/html/2402.01118v1).
- PokéChamp (Karten et al., ICML 2025): LLM replaces action sampling, opponent modeling and value estimation inside minimax; "projected Elo of 1300-1500" = top 30%–10% of human players, measured over 50 ladder games with ~1/3 timeout losses (76% win excluding timeouts); 84% vs Abyssal bot, 76% vs PokéLLMon (GPT-4o) in Gen 9 OU; with Llama 3.1 8B still 64% vs PokéLLMon GPT-4o; "at least 25 matches between any two methods ... minimum of 100 games per method for Elo"; avg game 15.7 turns; 3M+ game dataset with 500k+ high-Elo; no latency/cost reported — [arXiv 2503.04094](https://arxiv.org/html/2503.04094v1).
- Metamon (Grigsby et al., Apr 2025): offline RL transformers on reconstructed human logs; "best agents climb to rankings inside the top 10% of active players" on the ladder; beat "a recent LLM Agent approach and a strong heuristic search engine"; checkpoints/datasets at metamon.tech — [arXiv 2504.04395](https://arxiv.org/abs/2504.04395).
- PokéAgent Challenge (NeurIPS 2025 → living benchmark, Mar 16 2026 paper): 100+ teams, 100K+ battles; ratings = Full-History Bradley–Terry with bootstrapped uncertainty (primary), Glicko-1, GXE, stress-tested on "1.6M+ agent matches" with systematic rank disagreement beyond rank 4; organizer baselines PokéChamp, Metamon (RNNs to 200M-param transformers), FoulPlay (root-parallel MCTS), heuristics; "Specialist methods outperform generalist LLMs"; winners PA-Agent (Gen 1 OU) and FoulPlay (Gen 9 OU); live leaderboard at pokeagentchallenge.com — [arXiv 2603.15563](https://arxiv.org/html/2603.15563v1); [Smogon thread](https://www.smogon.com/forums/threads/pok%C3%A9agent-challenge-neurips-2025-pok%C3%A9champ-metamon-are-open-source-highly-ranked-ai-battlers.3772550/).
- API/speed: poke-env (Python) drives a local Showdown server; "a random agent can play about 100 randombats games in ten seconds"; a Showdown fork removes battle delays/rate limits; `max_concurrent_battles` enables parallelism — (snippet; unverified) [poke-env docs](https://poke-env.readthedocs.io/en/stable/); [hsahovic/Pokemon-Showdown fork](https://github.com/hsahovic/Pokemon-Showdown).

### Inferences
- A program-as-strategy design (LLM writes a poke-env bot, no LLM at inference) would be evaluated against bots that DO use LLMs at inference (PokéChamp) or large offline-RL models (Metamon); the PokéAgent ladder gives an honest anchor but published LLM numbers are not apples-to-apples with evolved programs.
- Cost per battle for LLM-at-inference agents is ~15.7 turns x (1–several) frontier-model calls; for evolved programs it is ~0.1 s of sim time. The human ladder also caps throughput (one battle at a time per account, timeouts cost PokéChamp ~1/3 of games).
- Team-building is a natural transmissible artifact (a team file is a few hundred bytes) and the format meta drifts with Smogon tiering changes, which is a confound for "thousands of generations" comparisons.

### Gaps
- No source gives $ cost or latency per battle for PokéLLMon/PokéChamp.
- No quantified meta-drift study was found.
- The "100 games / 10 s" throughput is a docs snippet, not a benchmark.

## KQ5. LLM program-evolution on games: papers, evaluation designs, FunSearch/AlphaEvolve/ShinkaEvolve game applications

### Takeaway
As of Oct 2026 the LLM-evolves-game-code literature is thin but has a clear core: DeepMind's two AlphaEvolve-on-OpenSpiel papers (exploitability + SCO/AlphaRank vs fixed-budget MCTS), FAMOU (co-evolving evaluator pool for a 3v3 capture-the-flag), ASRO (PSRO in program space), CodeClash (Elo over 7 bot arenas), and the Connect-Four-vs-solver study; ShinkaEvolve/FunSearch have no game applications, and "Mutation Without Variation" documents the diversity collapse a population design must beat.

### Cited Findings
- Evolution through Large Models (Lehman et al., 2022): LLM as mutation operator in MAP-Elites producing Python programs for Sodarace walkers; not games — [arXiv 2206.08896](https://arxiv.org/pdf/2206.08896).
- ShinkaEvolve (Lange, Imajuku, Cetin; Sep 17 2025): tasks = circle packing (new SOTA in 150 samples), AIME, ALE-Bench competitive programming, MoE load-balancing loss; no game application; open source — [arXiv 2509.19349](https://arxiv.org/abs/2509.19349).
- AlphaEvolve (2025) frames candidates as algorithms evolved under automatic evaluation — [arXiv 2506.13131](https://arxiv.org/html/2506.13131v1); its game uses are the two DeepMind OpenSpiel papers in KQ1 ([2602.16928](https://www.alphaxiv.org/abs/2602.16928v2), [2609.33115](https://arxiv.org/html/2609.33115)).
- FAMOU — "Beyond Static Evaluation: Co-Evolutionary Mechanisms for LLM-Driven Strategy Evolution in Adversarial Games" (Li et al., Jun 9 2026): LLM-driven code evolution (OpenEvolve/ShinkaEvolve-style) for the MCTF 2026 3v3 maritime capture-the-flag; three mechanisms — evaluator co-evolution (champions added to the opponent pool), hierarchical deep evaluation replacing "unreliable few-game assessments", and weakness pressure prioritizing hard opponents; best combined score 0.526, 61.7% win vs unseen opponents; 1st in the AAMAS 2026 hardware round-robin; code on GitHub; generation counts/cost not stated — [arXiv 2606.10389](https://arxiv.org/abs/2606.10389).
- ASRO — "Game-Theoretic Co-Evolution for LLM-Based Heuristic Discovery" (Ke et al., Jan 30 2026): PSRO adapted to program space with solver and instance-generator pools expanded by LLM best-response oracles (DeepSeek-V3.2); T=8 iterations; on bin packing/TSP/CVRP it beats EoH (e.g., TSPLIB small 0.21% vs 0.77% gap) — [arXiv 2601.22896](https://arxiv.org/html/2601.22896v1).
- "Mutation Without Variation" (Gurkan, Stonedahl, Wilensky; Jun 3 2026): in LLM-driven program evolution "in 87% of chains, over 93% of mutations revisit a previously seen structural form", i.e., systematic structural homogeneity vs classical GP — [arXiv 2606.05408](https://arxiv.org/abs/2606.05408).
- CodeClash and the Connect-Four AlphaZero study: see KQ2 ([2511.00839](https://arxiv.org/html/2511.00839v1), [2604.25067](https://arxiv.org/abs/2604.25067)).
- Programs-that-read-opponent-code (IPD/Coin Game) with 10 meta-rounds: see KQ1 ([2512.00371](https://arxiv.org/html/2512.00371v1)).
- GAVEL evolves game RULES (Ludii) with LLMs, not players — [arXiv 2407.09388](https://arxiv.org/pdf/2407.09388).

### Inferences
- The evaluation designs that recur across these papers are: fixed-budget reference searchers (PUCT/MCTS at 50 ms or 1,000 sims), exact solvers as anchors (Pons for Connect Four), exploitability where tractable, co-evolving opponent pools / champion archives, and many simulations per comparison (1,000 in CodeClash; "hierarchical deep evaluation" in FAMOU). A population sandbox should adopt all five to be comparable.
- No published work combines LLM program evolution with explicit teaching/credit/migration across groups, so the startup's claim would be novel; the nearest baselines are single-lineage (AlphaEvolve/ShinkaEvolve) or single-codebase (CodeClash).

### Gaps
- No LLM-evolved Othello/chess-engine/Battlesnake/Robocode papers beyond CodeClash were found; searches for "LLM evolves Othello/chess engine" returned LLM-plays (action-level) benchmarks (GAMEBoT, TextArena) only.
- Generation counts and $ cost are missing from FAMOU and the DeepMind papers.

## KQ6. Methodology: evaluating against frozen past generations (AlphaStar league etc.) and games per Elo estimate

### Takeaway
AlphaStar's recipe — snapshot frozen players every 2e9 steps, train 35% self-play / 50% PFSP vs all past players / 15% vs forgotten players, track Elo vs the whole league with the built-in Elite bot pinned at 0, and verify non-cycling via the league Nash support — is the template; rating precision needs on the order of 100–1,000 games per pair (AlphaStar validation used 160 games, CodeClash 1,000 sims, PokéChamp ≥100 games/method, Game Arena ~100 matches/pair or 20,000 poker hands).

### Cited Findings
- AlphaStar (Vinyals et al., Nature 2019): "Training Elo of agents in the League ... Each point represents a player, evaluated against the entire League and the Elite built-in bot (whose Elo is set to 0)"; robustness measured by "Proportion of Validation Agents that beat the main agents in more than 80 out of 160 games"; "The league Nash equilibrium over all players at each point in time assigns small probabilities to players from previous iterations, suggesting that the learning algorithm does not cycle or regress" (e.g., player 40 in the Nash from day 20 for 5 days); Main Agents: 35% SP, 50% PFSP vs all past players, 15% vs forgotten main players/past main exploiters; "Every 2e9 steps, a copy of the agent is added as a new player to the League"; League Exploiters frozen into the league when they beat all players >70% or after 2e9 steps, 25% chance of reset; Main Exploiters added when all three main agents are beaten >70% or after 4e9 steps; PFSP weights f_hard(x)=(1-x)^p and f_var(x)=x(1-x); Battle.net evaluation used 30/60/30 games per race across three snapshots, final MMR 6,275 Protoss (above 99.8% of players) — [AlphaStar Nature paper (unformatted PDF)](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf).
- Rosin & Belew (1997) introduced the hall of fame (evaluate against archived best-of-generation opponents) on Nim and 3-D Tic-Tac-Toe to encourage arms races; cycling is more likely under intransitivity — [New Methods for Competitive Coevolution (Semantic Scholar)](https://www.semanticscholar.org/paper/New-Methods-for-Competitive-Coevolution-Rosin-Belew/e276d83398222f2e55f7267e48d58e5cbf40341a); hall-of-fame analysis in RTS self-learning — [Springer](https://link.springer.com/chapter/10.1007/978-3-642-44973-4_19).
- Balduzzi et al. (ICML 2019) "Open-ended Learning in Symmetric Zero-sum Games": Nash of a population is the mixture that beats or ties all others; rectified Nash response (PSRO_rN) uses game-theoretic niching for diverse populations; Nash averaging ("Re-evaluating Evaluation") is invariant to redundant/weak agents — [arXiv 1901.08106](https://arxiv.org/pdf/1901.08106); [arXiv 1806.02643](https://arxiv.org/pdf/1806.02643). Clone-invariant "Deviation Ratings" (2025) extend this — [arXiv 2502.11645](https://arxiv.org/pdf/2502.11645).
- Games per Elo estimate: 95% error ≈ 1362*sqrt((score*(1-score) - drawratio/4)/(ngames-1)) Elo points — (snippet; forum source) [TalkChess](https://talkchess.com/forum3/viewtopic.php?t=57969); Elo's rule of thumb "approximately 30 games give a 95% confidence level ... 100 games 99%" — (snippet; forum) [Chess.com forum](https://www.chess.com/forum/view/off-topic/elo-rating-confidence-levels-based-on-number-of-games). Practice in the papers above: 160 games per validation pair (AlphaStar), 1,000 sims per round and 98% bootstrap order agreement (CodeClash), ≥100 games per method (PokéChamp), ~100 matches per pairing / 20,000 duplicated poker hands (Game Arena), bootstrapped FH-BT (PokéAgent).
- Lux S3 winners used the same idea (versioned model libraries + prioritized fictitious self-play) — [zenn summary](https://zenn.dev/kurupical/articles/61dbeedf89a29d). The 2026 DeepMind paper adds "stochastic quorum scheduling" and SNR-optimized calibration budgets to control evaluation noise — [arXiv 2609.33115](https://arxiv.org/html/2609.33115).

### Inferences
- Plugging the formula: at a 50% score with no draws, ±50 Elo (95%) needs ~190 games; ±25 Elo needs ~740; ±10 Elo needs ~4,600 games per pair — which is why simulator speed dominates the budget for thousands of generations.
- The cleanest anti-cycling check that is not game-specific is AlphaStar's: compute the Nash of the frozen-ladder payoff matrix each generation and show support concentrates on recent players; alpha-rank/SCO in OpenSpiel implement this off the shelf.

### Gaps
- The Elo-error formula and "30 games" rule come from forum sources; a textbook/Glicko derivation (Glickman) would be the primary citation.

## KQ7. Scorecard: which candidates have an ABSOLUTE metric vs only relative Elo (synthesis of the above)
